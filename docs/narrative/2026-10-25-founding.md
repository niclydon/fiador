# Founding: why this repo exists

October 25, 2026

This project started in a Discord conversation about how anyone
in a server is supposed to tell an agent acting for a real person
from an unattended bot swarm. The honest answer, today, is that
they cannot. Profiles do not say, verification checkmarks mean
something else, and the one system that can prove a unique human
stands behind an agent, World's AgentKit with its AgentBook
registry on World Chain, has no Discord integration at all.

So the author got verified. An Orb scan in New York, an agent
wallet registered in AgentBook, and a day of prototyping against
the live registry: a gated endpoint that serves registered agents
and refuses everyone else, the free trial exhausting after three
uses exactly as designed, the whole loop proven end to end on
October 25, 2026. The substrate works. What did not exist was
everything between that substrate and a server admin who wants to
know which bots in their member list have a person behind them.

A round of public research the same weekend confirmed how empty
the space is: the AgentBook registry linked from World's official
documentation contains five services in total, and no public
implementation of agent attestation for messaging platforms
exists in any form. human-backed is the attempt to build that
missing piece in the open, as neutral infrastructure rather than
a product: a signed attestation any operator can publish, a
registry anyone can read, a verifier any admin can run
themselves, and a static page for everyone else.

The founding decisions, each argued out and recorded before any
code moved here:

- The proof claims one thing only: a unique verified human
  registered the signing wallet. Not authorship, not endorsement,
  not present control. The badge and every page in this project
  repeat that limit, because the fastest way to kill a trust mark
  is to let it imply more than it proves.
- Attestations publish a hash of the human identifier, never the
  value itself. Verification never needed the raw identifier
  public; a permanent, crawlable correlation key across every
  agent a person runs would betray the anonymity that makes the
  underlying system worth building on.
- The verifier is self-hosted. A central bot with role-granting
  power in every adopting server would rebuild exactly the
  concentrated trust this protocol exists to dissolve, and would
  make its operator the ecosystem's favorite target.
- The name carries no World marks, and the author credit rides on
  the Apache-2.0 NOTICE rather than branding: this is meant to be
  infrastructure other people can adopt without adopting someone
  else's product identity along with it.

What happens next is in the spec's build order: the verify
package first, then the static page, then the verifier bot,
tested end to end in the author's own server before anyone else
is asked to care. Every arc of that work gets an entry in this
folder and a line in CHANGES.md, including the failures. If a
claim in this repo is ever found to outrun its evidence, the
correction lands here too.

Pre-publication record for this founding tree: secret scan and
privacy read performed over the full tree before the first push
(patterns for private keys, tokens, full human identifiers,
personal data, and internal infrastructure details); results in
the repository's first commit notes. Nothing in the founding
tree derives from private systems; the specification and assets
were authored for publication.
